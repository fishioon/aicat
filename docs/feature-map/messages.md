# 统一消息

常驻「消息」导航是后台会话的记录与排查入口。224px 会话列表显示名称、最近摘要、渠道、最近活动和异常，支持按名称/渠道/标识搜索及「全部会话 / 异常」筛选。消息以成员与 aicat 回复两侧排版，使用项目 logo 作为 aicat 回复头像；左侧导航不显示品牌标识，也不显示未读或记录阅读位置。选择会话不改变消息、任务或发送状态。

列表搜索旁和空列表提供「添加消息渠道」，跳转扩展页并将搜索设为 `tag:channel`，选中一个可用的消息渠道条目；入口不安装或启用渠道，未保存的Room设置仍须确认放弃。扩展页的筛选随前进/后退恢复。

会话消息展示最近200条入站、业务摘要、正式回复与外发状态；JSON原始业务消息默认折叠，引用可以定位关联消息。同业务对象的旧状态回复标明较早局面。卸载渠道不移除历史。

异常筛选包含持久外发请求中的 failed / unknown，以及本次运行保留任务中的 failed / unknown；查看不会清除异常，较早外发异常不因消息超出200条展示窗口而消失。右侧「处理记录」面板展示异常原因、可用的关联消息、任务状态和执行信息，不提供自动重发。任务记录不跨应用重启保留，外发回执保持持久。界面如实区分本地保存、渠道确认、失败和结果不明，不把渠道确认视为对端已读。

Room设置在右侧面板编辑，默认显示名称、自动处理与外发授权；平台寻址按渠道能力展示，会话标识、触发条件默认折叠。高级配置默认折叠，包含 model、Room prompt、文本JSON context和conversation/snapshot模式；只有展开高级配置才向实际执行入口读取模型列表，空值使用Codex默认。触发条件保留全量/私聊/提及/所有人/关键词的组合。未保存设置不被状态刷新覆盖，切换Room或关闭面板提示丢弃修改。保存校验失败保持原配置，后续任务使用新配置。

消息页通过typed Desktop服务读取，变更通知刷新，无额外轮询或插件业务页面。Desktop与HTTP查询复用宿主的异常聚合，不读写旧阅读标记文件。

后台定向验证：`make e2e-build` 后执行 `node e2e/messages.cjs bin/aicat-e2e build/messages-<run>`。真实NPM安装/宿主、Room、Codex协议夹具、HTTP MCP、隐藏应用及headless浏览器共同覆盖接入到回复/外发链路、添加消息渠道与tag筛选/关键词/导航恢复、搜索与异常筛选、查看不修改状态、旧阅读标记忽略、高级配置折叠与按需模型查询、草稿保留/校验/保存、结构化正文、回复关联、发送异常跨展示窗口及重启保留、卸载后查阅，以及中英文、浅深色和1180/860宽度。输出报告、运行日志、源码/二进制摘要、协议轨迹和截图。

`node e2e/rooms.cjs bin/aicat-e2e build/rooms-<run>` 额外覆盖完整Room调度、配置、权限和账号隔离。独立 [aicat-wpk](https://github.com/fishioon/aicat-wpk) 仓库的 E2E 将采集到的同一 Room 及 MCP 结果在消息页验收。平台与模型夹具不代表真实送达或真实模型能力；这些入口均不操作真实桌面或账号。
