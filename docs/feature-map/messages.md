# Room 管理

常驻「消息」导航是 Room 管理页。左侧列出所有渠道的 Room，显示名称、渠道和自动处理状态，支持按名称、渠道或标识搜索；右侧编辑选中 Room 的设置。页面不展示聊天记录、任务或发送记录：聊天内容在平台本身查看，Agent 外发、定时触发与任务执行写入 `logs/aicat.log`。

Room 名称优先显示用户自定义名称，其次使用渠道同步的平台名称，再次使用平台会话标识。列表按最近平台消息时间排序。卸载渠道后 Room 仍保留在列表中。

列表搜索旁和空列表提供「添加消息渠道」，跳转扩展页并将搜索设为 `tag:channel`；入口不安装或启用渠道，未保存的 Room 设置须确认放弃。

## Room 设置

右侧面板默认显示名称与自动处理；会话标识、触发条件默认折叠。平台寻址由渠道插件自行完成，Room 设置不包含外发名称。高级配置默认折叠，包含 model、Room prompt 和文本 JSON context；只有展开高级配置才向实际执行入口读取模型列表，空值使用 Codex 默认。

触发条件由三组独立开关组成，任一命中即触发：

- Chat 模式：别人私聊，或群聊中真实 @ 当前账号。
- 规则匹配：正则匹配别人发送的消息。
- 自己发送的消息：正则匹配当前账号发出的消息。Agent 的回复回流后也属于自己发送的消息，需确保回复不会匹配。

节点默认值来自 `aicat.yaml` 的 `roomDefaults`，Room 的覆盖设置和持久 thread 状态保存在 `rooms/<稳定ID>/room.json`。未保存设置不被状态刷新覆盖，切换 Room 或点「添加消息渠道」时提示丢弃修改。保存校验失败保持原配置，后续任务使用新配置。

页面通过 typed Desktop 服务读取，变更通知刷新，无额外轮询或插件业务页面。

## 验证

后台定向验证：`make e2e-build` 后执行 `node e2e/messages.cjs bin/aicat-e2e build/messages-<run>`。真实 NPM 安装与宿主、Room 存储和 headless 浏览器覆盖 Room 列表与搜索、添加消息渠道跳转、设置草稿保留、校验与保存、三组触发条件、高级配置折叠与按需模型查询，以及中英文、浅深色和 1180/860 宽度，输出报告、运行日志与截图。

`node e2e/rooms.cjs bin/aicat-e2e build/rooms-<run>` 额外覆盖完整 Room 调度、触发、配置、权限和账号隔离。平台与模型夹具不代表真实送达或真实模型能力；这些入口均不操作真实桌面或账号。
