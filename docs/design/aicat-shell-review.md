# aicat-shell 设计稿 Review

日期：2026-11-11
对象：`docs/design/aicat-shell.html`（首页/网关概览、接入 Agent、流量、设置），并对照 `ui/src/design.css` 与 `build/full-e2e-rp51dwcq/desktop/` 下的实现截图。
方法：通读设计稿源码，查看 e2e 生成的 design-reference / design-actual 截图，在预览面板里渲染了首页，并用脚本计算了色板对比度、统计了未使用的样式。没有在真实宿主里逐页点击，交互结论来自源码。

## 结论

整体骨架（标题栏 + 导航栏 + 侧栏 + 主区）、色板的明暗两套取值和容器查询的响应式都做得扎实，深色模式的对比度全部达标。不够好的地方集中在四类：设计稿自身不能独立正确渲染；流量页作为核心页面，信息密度够但"看内容"的能力偏弱；品牌色承担了太多含义；稿子里留着不少已放弃方向的残留，和实现也已经分叉。

下面按优先级排列。正文记录的是修改前的状态。

## P0 先修

### 1. 设计稿脱离宿主就渲染不对，e2e 的参考截图也因此失真

文件是一个没有 `<!doctype>`、没有 `<meta charset>`、也不自带图标库的片段，依赖宿主提供 `lucide`。后果有三个：

- 图标全部空白。`e2e/design.cjs` 生成的 `design-reference-*.png` 里导航栏选中项是一个空方块，搜索框、复制按钮、树的展开箭头都没有图标。`e2e/design-shots.cjs` 注入了 lucide，但 `design.cjs` 没有。
- 深色下请求 Header 表格的文字几乎看不见（见 `design-reference-dark.png` 左下）。`.ac-header-table td` 没有显式颜色，推测是无 doctype 进入怪异模式后表格不继承父级颜色所致；实现截图里是正常的。
- 直接打开时中文是乱码（预览面板里 "Agent Gateway · 设计预览" 显示为乱码）。

建议：给 `.ac-header-table` 显式写 `color:var(--ac-text)`；`design.cjs` 用带 doctype 和 charset 的外壳加载并注入 lucide；或者干脆把稿子改成可独立打开的完整 HTML。

### 2. 设计校验只比了 10 个尺寸和 1 个颜色，"通过"不代表一致

`design-report.json` 显示 passed，但同一次运行的参考图和实际图差别很大：稿子有首页（网关概览）和接入页，实现没有；实现有"扩展"页和"应用"分组，稿子没有；侧栏分组顺序、搜索占位文案、设置的分类（稿子是通用/代理/功能，实现是代理/通用）都不同。`docs/development.md` 已说明稿子含未交付方向，但没有说明哪些页面以稿子为准、哪些以实现为准。

建议：在稿子顶部或 `development.md` 里列一张"页面 × 状态（已交付 / 设计中 / 已放弃）"的表；把扩展页和应用分组补回稿子，或者明确稿子只对流量页负责。

### 3. 浅色模式有几处对比度不达标

脚本按 WCAG 公式计算的结果（深色模式全部通过，不再列出）：

| 位置 | 组合 | 对比度 | 要求 |
| --- | --- | --- | --- |
| Raw 行号 | muted 75% 透明度 / surface | 3.02 | 4.5 |
| 输入框占位文字 | muted 85% 透明度 / surface | 3.66 | 4.5 |
| hover 行上的次要文字 | muted / soft | 4.20 | 4.5 |
| 选中行上的次要文字 | muted / brand-soft | 4.36 | 4.5 |
| 侧栏选中项文字 | brand-text / brand-soft | 4.40 | 4.5 |
| 焦点环 | brand `#00bba7` / surface | 2.42 | 3 |
| 输入框、按钮描边 | border / surface | 1.30 | 3 |
| 斑马纹 | stripe / surface | 1.07 | 几乎不可见 |

这些文字大多是 11px，本来就小。建议浅色的 `--ac-muted` 再压深一档（约 `#62626b`），行号和占位文字不要再叠透明度，焦点环在浅色下改用 `--ac-brand-text`，斑马纹要么加深要么去掉。

## P1 流量页

### 4. 检查器只有 Header 和 Raw，看不了正文

这是一个面向 AI 流量的调试工具，但 JSON 正文在 Raw 里是不换行、不格式化的一整行（`wireBody` 直接 `JSON.stringify`），SSE 响应没有按事件拆分的视图。文案表里已经有 `bodyTab`、`queryTab`，却没有渲染。建议补上 Body（格式化 + 折叠）、Query，以及 SSE 的事件列表视图，并设计流式进行中和正文被截断两种状态；实现里截断提示目前是 "正文状态 truncated · 保留 65536 B / 已观察 280058 B"，夹着英文原词，需要稿子给出正式文案。

### 5. 状态只有"成功"和"≥400"两种

列表里 204、304 和 200 同为绿色，401 只靠一个 11px 的红色数字区分；没有进行中、无响应、超时、连接失败的样式；方法列全是灰色。fixture 里有 `type`（JSON / SSE / TUNNEL）但表格没有这一列。筛选只剩 URL 模糊搜索，`modified`、`errors` 两个筛选在 `normalize()` 里被强制重置。建议至少补：3xx 中性色、进行中状态、类型列、按状态/方法的快速筛选。

### 6. 列表不能用键盘上下移动

行的点击绑在 `<tr>` 上，可聚焦的只有 URL 按钮，`keydown` 里没有处理行间的方向键。对抓包工具来说，上下键切换请求是最高频的操作。两个检查器标签也都可以被 Tab 到，没有做成 roving tabindex。

### 7. 左边缘不对齐

主区从上到下的左内边距依次是：面包屑 21px、工具栏 14px、表格首列 14px、详情标题 12px、检查器栏 10px、Header 表格 10px、底栏 14px。参考截图里能看到"流量 / 搜索框 / 方法胶囊 / 请求"四条左边线各不相同。建议统一为一个内边距变量。

### 8. 空状态占了整屏却没有引导

没有请求时，上半屏是一行"等待流量 · 将客户端代理配置为…"，下半屏是"未选择请求"。建议此时收起详情区，把上半屏做成真正的引导：可复制的代理地址或命令、跳到接入页的入口。

### 9. 其他

- "清空"紧挨搜索框，一点即清，没有确认也没有撤销。
- 每次选中请求都会写入前进/后退历史（`visit()`），点过十条请求后，后退要按十次才能回到上一个页面。建议历史只记录页面和筛选的变化。
- 详情标题里的方法胶囊用品牌色加描边，看起来像一个可点的、已选中的按钮。
- 截断的 URL 只靠宿主提供的 `data-tooltip` 才能看全。

## P1 色彩与语义

### 10. 品牌青色承担了太多含义

同一个青色同时表示：选中、当前标签、链接/文字按钮、URL 主机名、方法胶囊、JSON 字符串、请求行、录制中、代理监听中，以及"待重启"。其中"待重启"是需要用户处理的状态，却和"一切正常"的指示点同色，而旁边的提醒图标用的是警告色。

另外浅色下成功绿 `#18794e` 和品牌青 `#087e73` 几乎是同一个颜色（两者互相的对比度 1.09）。首页上"正常"（状态）和"开启""设置"（操作）并排在右侧，看不出哪个可以点。

建议：品牌色只留给"选中"和"主操作"；状态用 success / warning / danger；语法高亮单独取色；右侧的文字操作加上明确的按钮外形或箭头。

## P2 首页与设置

### 11. 首页

- 命名不统一：预览条写 "Agent Gateway"，面包屑是"首页 › 概览"，大标题是"节点网关"，状态行是"本机节点"，正文里又是 aicat / AICat。
- 同一个失败出现三次：Agent 行的红字说明、行尾的"有失败"、近期调用里的"编译失败"。Codex 4 次调用失败 1 次且发生在 18 分钟前，整行标红偏重。
- MCP 和 HTTP API 地址是接入时最需要的信息，却放在页面最底部的 11px 小字里。
- 容器宽度 ≤800px 时，近期调用的状态行有 39px 左缩进（`.ac-gw-activity-trailing`），这是给已经删掉的图标留的位置，现在状态文字和工具名错开了。
- 提醒条"改写规则已更新，重启后生效"和能力列表里的"待重启"重复，能力那一行又没有操作入口。

### 12. 设置

- "功能"里的开关是浏览器原生复选框，而稿子里定义了 `.ac-switch` 却没有用。
- "代理"页的系统代理和本机 CA 只是"已启用""已信任"两个静态徽标，没有开关、安装、撤销等操作，也没有未启用、未信任、失败的状态。
- 示例数据自相矛盾：设置页显示"已启用 / 已信任"，首页能力列表同时写着"系统代理未接管 · 证书未安装"。
- 设置入口只藏在左下角头像菜单里；头像在未登录时也是实心品牌色的 "AC"，容易被当成已登录。
- `sideItem()` 接收了图标参数但没有渲染，设置侧栏是纯文字。

## P2 设计系统

### 13. 没有字号、圆角、间距的阶梯

字号出现了 9、10、11、12、13、14、17、20、21、24 共十档，圆角有 3、4、5、6、7、8、9、12、20 九档（5/6/7 混用），内边距有 10、12、14、15、17、21、24、28。颜色有变量，其余全是散落的数值。建议收敛为 4–5 档字号、3 档圆角、一组 4 的倍数的间距，并做成变量。10px 的文字（徽标、键帽、头像）建议最小提到 11px。

### 14. 稿子里有不少残留

- 12 个定义了但没有使用的样式类：`ac-code`、`ac-detail-tabs`、`ac-diff`、`ac-field`、`ac-gw-capability-content`、`ac-home-empty`、`ac-payload-heading`、`ac-property-list`、`ac-rule-row`、`ac-section-title`、`ac-side-heading`、`ac-switch`。
- 同一选择器在文件里被后面的规则覆盖：`.ac-listen-editor` 宽度 270 → 248，`.ac-gw-activity` 内边距 16 → 11，`.ac-gw-notice` 对齐 start → center，`.ac-home h2` 21px → 17px，`.ac-home-footer code` 重复声明。
- 文案表里留着已放弃方向的键（模型路由、AI 调用量、重放请求、改写记录等），`replay`、`copy` 两个动作也没有任何按钮触发。
- 两套国际化写法并存：`t('key')` 查表，和 `gatewayText('中文','English')` 内联。
- `ui/src/design.css` 开头写着"与设计稿保持一致"，但里面还有稿子已删除的 `.ac-gw-summary`、`.ac-gw-provider`、`.ac-gw-service` 等一批规则。

### 15. 无障碍细节

导航按钮用 `aria-pressed` 表示当前页，应为 `aria-current="page"`；头像菜单里方向键只会跳到第一个按钮；可点击的表格行没有键盘等价操作（见第 6 条）。

## 附：从实现截图里顺带看到的问题

这些不属于设计稿，但在 `build/full-e2e-rp51dwcq/desktop/` 的截图里很明显：

- 标题栏右侧的主题按钮比同排的导出图标低了几个像素（所有 actual 截图）。
- 英文界面下，语言设置的说明和侧栏底部的"代理监听中"仍是中文（`general-dark-en.png`）。
- 扩展页的"关闭"按钮是高亮的品牌色胶囊，分不清它表示"当前已关闭"还是"点击关闭"（`extensions-light.png`）。

## 建议的处理顺序

1. 修第 1 条（三行改动），让参考截图可信。
2. 调浅色 muted、焦点环和行号（第 3 条），改动只在变量层。
3. 统一主区左内边距（第 7 条）。
4. 为流量页补 Body / SSE 视图和状态体系（第 4、5、6 条），这是产品价值最大的一块。
5. 收拢品牌色的语义（第 10 条）。
6. 清理残留并建立字号、圆角、间距变量（第 13、14 条），同时同步 `design.css`。
7. 明确稿子与实现各自的权威范围（第 2 条）。
