# aicat 重新设计：交接说明

日期：2026-11-11
用途：给后续在代码模式下继续工作的会话看。读完这一份就能接着做，不需要之前的对话。

## 现在的状态

新设计稿是 `docs/design/aicat-redesign.html`，一个可独立打开的完整 HTML（带 doctype、内联图标和脚本，不依赖宿主或网络）。它只是设计稿，还没有落到 `ui/` 的实现里。

没有改动的东西：旧稿 `docs/design/aicat-shell.html`、`ui/` 下的全部代码、e2e 脚本、`CONTEXT.md` 和 README。仓库里原本就有一批未提交的改动，都不是这次产生的；这次新增的只有设计稿和本文件。

上一轮对旧稿的 review 在 `docs/design/aicat-shell-review.md`，新稿处理了其中大部分问题。

## 已定的前提

交付物是新的独立设计稿，范围是整个外壳。

第一版稿子曾按"视觉全部重来"做成顶部文字页签加黄色品牌色。用户看过后改了两点，现在的稿子以这两点为准：

1. 保留最左侧的图标导航栏。模块入口放回左侧，标题栏空出来给前进后退和面包屑。
2. 颜色不脱离公司设定。品牌色是青色 `#00bba7`（`docs/phase-one-design.md` 写明沿用 netcat 网站，`assets/logo.svg` 的尾巴也是这个颜色），底色是中性灰。

## 设计方向

骨架分四块：

- 标题栏 44px：前进、后退，面包屑（模块 › 子页面，流量页显示当前筛选），常驻的监听地址（点击复制代理地址），主题按钮。
- 图标导航栏 52px：概览、流量、扩展、更多，底部是设置。流量只在扩展启用且固定时出现。当前项只用品牌色图标加浅底表示，不加左侧竖线，避免和窗口边框叠在一起。
- 侧栏：流量和设置是 224px，扩展是 272px，概览没有侧栏。
- 主区。

"更多"浮层列出模块，点行打开，点图钉固定或取消固定。取消固定后，流量仍可从"更多"进入，此时"更多"按钮显示为当前位置。"更多"是导航栏的收纳处，不是"已启用模块"的清单：模块多了以后，不常用的取消固定，就收在这里。

概览是全局用量总览，不再用接线图。接线图在扩展变多以后放不下，也说不清它想表达什么；`CONTEXT.md` 对首页的要求是"网关状态、接入地址、能力配置、用量摘要与连接异常"。从上到下是：

- 标题行：网关状态、已接入的 Agent 和供应商数量，右侧是"接入供应商""接入 Agent"两个入口。
- 时间范围：今天、7 天、30 天。
- 五个数字：Token（输入、输出、缓存）、请求（失败数和成功率）、费用（按公开价目估算）、缓存命中率、输出速度（含首字耗时）。
- 用量趋势：堆叠柱状图，指标可切 Token、费用、请求，拆分维度可切模型、供应商、Agent。右侧图例带每项的合计、请求数和占比。悬停或用方向键移到某根柱子上显示该时段明细。
- 已接入：Agent 和供应商的列表，各带请求数和最近活动。
- 需要处理：连接异常和等待确认的事项（例如某个 Agent 的 401、改写规则待重启），各带一个操作按钮。
- 接入地址：MCP、HTTP API、HTTP 代理。

图表的三个系列色是 `--s1`、`--s2`、`--s3`（蓝、橙、紫），避开了品牌青和成功绿，明暗两套都用 dataviz 的校验脚本验证过。颜色跟随实体而不是排名，切换范围或维度时同一个模型、供应商或 Agent 颜色不变。

"接入供应商"是一个子页：选供应商（Anthropic、OpenAI、兼容 OpenAI 的服务），填接口地址和 API Key，然后把 Agent 的模型地址指向 aicat。这对应产品方向里的"上游模型路由"，后端还没有实现，页面顶部有一行说明它是方向稿；环境变量和路径（如 `/anthropic`）是示意，以最终实现为准。

四条规则（也写在稿子顶部的注释里）：

1. 品牌青只表示 aicat 自己、当前位置、这一屏的主操作。状态一律用 ok / warn / bad。浅色下的细线标记和焦点环用 `--mark-line`，大面积填充用 `--mark`。
2. 正常是安静的：2xx、已连接、已信任的文字都用正文色，只有需要看的才上色。请求列表行首的状态点是例外，成功也给绿点，方便扫视。
3. 数字和地址用 `--num`（DIN Alternate），代码用 `--code`，其余用 `--ui`（系统中文字体）。
4. 字号 11 / 12 / 13 / 15 / 20 / 28；圆角 4 / 8 / 12；间距取 4 的倍数；主区左边线统一为 `--gutter`（16px）。

品牌青和成功绿在浅色下几乎分不开（上一轮 review 算过互相的对比度只有 1.09）。稿子靠形态区分：品牌色只以线条和填充出现，状态只以"圆点 + 文字"出现，品牌色不做圆点。

## 稿子里各页的内容

- 概览：已接入时是上面说的用量总览；首次接入时是两步引导（接入 Agent、接入供应商）加接入地址，由窗口上方的预览条切换。两个子页："接入 Agent"（选客户端、复制配置、等待首次连接）和"接入供应商"。
- 流量：侧栏按 固定 → 域名 → 应用 分组，可展开到路径；列表参考 Proxyman 和 Rockxy：行首是状态点（绿 = 2xx，红 = 4xx / 5xx / 失败，灰 = 3xx，空心 = 未解密的隧道，转圈 = 进行中），后面依次是编号、URL、应用、方法、状态、类型、耗时、大小；有按状态的快速筛选；详情是请求、响应双栏，视图有 Header、Query、Body、事件（SSE）、Raw；CONNECT 记录显示加密隧道说明和"解密此域名"；空状态给出可复制的 curl 命令；清空可撤销；↑ ↓ 选择，Esc 取消，⌘K 聚焦搜索；右键菜单有复制 URL、复制 cURL、固定域名。
- 扩展：参考 VS Code 的扩展视图。侧栏 272px（比其他模块宽，因为每行要放图标、名称、状态和一行简介），顶部是搜索，下面是可折叠的已安装、推荐两组，各带数量。内置扩展归在已安装里，名称旁带"内置"标记；`CONTEXT.md` 写的是已安装、内置、推荐三组，采纳时要改。每个扩展占两行：第一行是名称和右侧的启用状态，第二行是简介；发布者只在详情页显示。主区是所选扩展的详情：大图标、名称和"内置"标记、发布者、简介，然后是操作区：一个小号实心按钮（已启用时是灰色的"停用"，已停用时是品牌色的"启用"）加一个齿轮，齿轮菜单里是打开流量、代理设置、复制扩展标识符。操作区不放状态文字，只有停用时才在按钮下面多一行说明。再下面是"详情""功能"两个页签，右侧一列是标识符、发布者、来源和分类。推荐一组目前只有占位说明，没有安装操作，也没有虚构的扩展条目。停用后导航栏里的"流量"消失。用词统一成"启用 / 停用"。
- 设置：通用（语言、主题）和代理（监听地址、根证书、系统代理、解密域名），各状态都能点出来。解密域名支持通配符：`*.example.com` 匹配它的所有子域名，不含 `example.com` 本身，和改写规则（`internal/rewrite/engine.go`）的语义一致；通配符只能写在最前面。后端 `internal/app/interception.go` 目前只做精确匹配，这一条需要后端跟着实现。

截图入口：稿子支持 hash 参数，例如 `aicat-redesign.html#page=traffic&theme=dark&sel=2234&resTab=body`。可用的键有 `page`、`theme`、`state=first`、`set`、`sel`、`reqTab`、`resTab`、`xtab`、`connect`（`1` 或 `provider`）、`range`、`metric`、`dim`。

## 验证到什么程度

用本机 Chrome 和 `e2e/` 里的 Playwright 跑过，脚本是 `build/redesign-shots.cjs`（在被 git 忽略的 `build/` 下），截图输出到 `build/redesign-shots/`。

- 渲染：二十三个画面无脚本报错。最近一轮逐张看过的是概览（浅色带悬停提示、深色 30 天按 Agent 拆分）、深色的流量列表、扩展页的各个状态和浅色的代理设置。首次接入、接入 Agent、接入供应商、900 宽的概览和流量这几张只确认了无报错，没有逐张看。
- 交互：在真实浏览器里断言通过——导航栏切换和面包屑、前进后退、侧栏筛选进入历史、↑ ↓ 选择、Esc 取消、⌘K 聚焦搜索、右键菜单和它的键盘操作、"更多"里固定与取消固定、Esc 关闭浮层并还原焦点、概览切换时间范围、指标和拆分维度、柱子的悬停提示和方向键、"查看请求"跳到对应记录、保存供应商密钥、扩展分组的折叠、扩展搜索、详情页签的左右键切换、齿轮菜单、解密域名对通配符的接受与拒绝、停用流量扩展后后退跳过流量页。
- 对比度：按 WCAG 公式算过文字、描边、标记线、状态色在各底色上的组合，明暗两套都达标（文字 4.5:1，描边和标记线 3:1）。
- 字体：macOS 上 DIN Alternate 的实际效果只在截图里看过，没有在应用窗口里看过。

## 稿子没做的

- 只有简体中文，没有英文。英文文案更长，按钮和设置行的宽度需要重新看。
- JSON 正文没有折叠；列表和详情之间的分隔条不能拖动。
- 前进后退只恢复模块、子页面和流量侧栏筛选。`CONTEXT.md` 要求的搜索词和所选请求没有纳入。
- 旧稿标题栏里的"折叠侧边栏"按钮没有放回来。
- 概览没有做参考图里的"模型速度"表和按周的用量热力图。原先的"近期调用"（经 /mcp 的请求列表）去掉了。
- 账号菜单和私云只在设置侧栏底部留了一句"私云未接入"。导航栏底部现在是设置入口；私云接入后，账号头像可以放在它上方。
- 托盘菜单不在范围内。

## 接下来要做的决定

1. 新稿是否取代旧稿成为权威。骨架和色板现在都和 `CONTEXT.md` 一致，剩下的差别是：尺寸从 48 / 53 / 216 变成 44 / 52 / 224；导航栏多了概览；设置从头像菜单改成导航栏底部的直接入口。如果采纳，`CONTEXT.md` 的"流量界面"一条和 README 里描述窗口的段落要跟着改。
2. `e2e/design.cjs` 和 `e2e/design-shots.cjs` 现在比对的是旧稿，换稿后要改比对对象和尺寸断言。
3. 概览页是新产品方向里的内容，`docs/feature-map/README.md` 把"节点首页、基础调用统计"和"上游模型路由"都列为尚未交付。概览上的 Token、费用、缓存命中率、输出速度，以及按模型、供应商、Agent 的拆分，后端目前都没有；稿子里全是演示数据。这些数字要从经过网关的模型响应里解析用量字段才能得到，费用还需要一份价目表。

## 落到 `ui/` 的建议顺序

前端在 `ui/src/`：`App.vue`、`design.css`、`layout.css`、`style.css`，组件有 `TrafficPage.vue`、`TrafficSidebar.vue`、`Inspector.vue`、`ExtensionsPage.vue`、`SettingsPage.vue`、`ModuleSidebar.vue`、`TreeRow.vue`、`Splitter.vue`、`Overlays.vue`。`App.vue` 已有标题栏（前进、后退、折叠侧栏、面包屑）和图标导航栏（流量、扩展、更多、头像），新稿的骨架和它是同一个结构，改动比第一版小。其余组件这次没有读过，动手前先看实际代码。

1. 色板：`design.css` 的 `--ac-*` 取值基本不用动，补上表里标"新增"的四项，再收拢散落的字号、圆角、间距。
2. 外壳：导航栏加概览、底部头像换成设置入口，标题栏加常驻的监听地址。
3. 流量页：状态体系、类型列、快速筛选、键盘上下移动，然后是 Body、Query、事件视图和截断提示文案。
4. 设置和扩展页：开关、证书各状态、解密域名列表。
5. 概览页放最后，先确认数据来源。

`AGENTS.md` 的约束仍然适用：功能开发只验证受影响的流程，全套 E2E 留到整轮结束再跑。
