# 界面设计语言

aicat 是运行在用户节点上的 Agent Gateway。界面服务技术用户的日常检查、接入和诊断，不是营销页面。整体设计以本地网络仪表台为方向：状态明确、数据密度适中、层级安静，装饰只用于解释结构。

## 视觉方向

- 主色为中性灰和白色，品牌青绿色只标记当前位置、主要操作和 aicat 自身状态。
- 成功、警告和错误使用语义色；图表分类色只服务数据辨识，不作为界面装饰。
- 页面依靠排版、间距、细线和留白建立层级，不依赖阴影、渐变或重复卡片。
- 整个应用只保留一个强视觉焦点：实时流量、网关状态或当前任务。其他区域保持克制。
- 非用户触发的动画只用于状态变化；不为页面进入、卡片出现或普通悬停添加强调动画。

## 色彩

| 用途 | 浅色 | 深色 |
| --- | --- | --- |
| 窗口框架 | `#f6f6f7` | `#252527` |
| 内容表面 | `#ffffff` | `#202022` |
| 下沉区域 | `#f2f2f5` | `#272729` |
| 正文 | `#242428` | `#e9e9ed` |
| 次级文字 | `#4b4b53` | `#c4c4cc` |
| 品牌青绿 | `#00bba7` | `#00bba7` |

## 字体

- 界面文字使用系统无衬线字体，优先 SF Pro 与 PingFang SC。
- 数字、地址和统计值使用窄体数字字体，保持表格中的垂直对齐。
- 代码、请求 ID、域名和正文片段使用等宽字体。
- 字号沿用 `11/12/13/15/20/28`，不增加只为装饰服务的字号。
- 标题使用明确字重建立层级，不通过彩色标题、首字变色或全大写标签制造重点。

## 布局

```text
┌──────────────── titlebar ────────────────┐
│ history  breadcrumb       status  theme  │
├────┬─────────────┬───────────────────────┤
│rail│ module side │ main canvas           │
│    │             │                       │
│    │             ├───────────────────────┤
│    │             │ inspector             │
└────┴─────────────┴───────────────────────┘
```

- 标题栏 `44px`，模块轨道 `44px`；模块侧栏按内容需要出现。
- 主内容左对齐，数据表、检查器和工具面板保持稳定的列结构。
- 概览页使用开放式区块和必要分隔线；只有需要独立操作或边界时才使用卡片。
- 流量页优先保证表格、筛选和检查器的信息密度，不把表格拆成卡片列表。
- 窄窗口优先收起侧栏和次要列，不压缩字号或堆叠所有控件。

## 状态层级

- 模块轨道：选中项使用中性灰背景和正文色图标，不改变图标尺寸。
- 模块侧栏：选中项可使用品牌浅色背景和左侧标记，表示当前文档或内容。
- 表格与列表：选中行使用浅色背景和清晰焦点，不复制模块轨道的选中样式。
- 同一层级只能有一个主要操作；主按钮使用品牌青绿，其余操作保持中性。

## 组件约束

- 圆角使用 `4/8/12` 三档；同一层级不混合不同圆角。
- 边框用于表达分组和边界；没有信息作用的分隔和容器应删除。
- 阴影只用于浮层、菜单、对话框和需要脱离文档流的元素。
- 空状态和错误状态说明发生了什么以及下一步做什么，不使用情绪化插图填补空间。
- 图标遵循[图标规范](icon-standard.md)；导航图标表达模块，工具图标表达操作。

## 文案

- 使用用户能够直接理解的名词和动词，不把内部实现名称暴露为界面主文案。
- 按钮文案说明执行后的结果，并在成功提示中保持同一动词。
- 空状态是行动的入口，错误文案说明原因和修复方式。
- 元信息使用统一的连接方式，但避免每行堆叠过多说明；能分列时优先分列。

## 设计检查

- 页面是否首先回答“当前发生了什么”和“我下一步能做什么”。
- 是否仍然只有一个品牌色信号层级，没有把分类色或状态色当作装饰。
- 内容是否由表格、列表、检查器和仪表结构组织，而不是被切成同质卡片。
- 标题、正文、辅助信息和操作是否具有清楚的阅读顺序。
- 空状态、失败状态、键盘焦点和深浅主题是否完整。
- 实际 WebView 截图是否与设计稿一致，并同时保留浏览器与原生覆盖说明。
