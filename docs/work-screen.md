# 虚拟工作屏

## 首版范围与实现前的失败清单

在桌面设置中手动开启一个共享的 1920×1080 工作屏，搬入已经打开的企业微信和 iPad 微信普通窗口。
使用当前托盘进程持有屏幕；关闭前恢复原窗口位置和尺寸，不自动随登录重建，不增加外部运行时。
运行意图只属于当前会话，不新增配置文件，也不向 `aicat.yaml` 写入自动启动开关。

实现和进程 E2E 需要覆盖以下失败：

- 私有显示 API 不存在、辅助功能未授权、没有实体主屏：创建前拒绝，不请求或改写权限。
- 显示创建和模式异步收敛、镜像/主屏意外改变：验证完整拓扑，未通过前禁止搬入窗口。
- 微信未运行、窗口不存在、最小化/全屏/模态窗口、AX 不支持搬移、AX/WindowServer 身份不唯一：明确显示状态，不操作其他窗口。
- 部分搬移成功后下一窗口失败：保留所有原位置和屏幕，允许关闭恢复。
- 重复开启或重复搬入：不覆盖最初的恢复位置、不重复创建屏幕。
- 原应用退出/重启或窗口关闭：不将旧窗口记录应用到新进程或替代窗口。
- 恢复被拒绝、屏幕中出现未登记窗口：拒绝销毁工作屏，显示错误并允许重试。
- 用户并发调整显示布局：不覆盖用户的新布局，恢复失败必须可见。
- 操作与发送并发、关闭时操作未完成：共用现有 GUI 锁，序列化管理动作，保持 AppKit 主循环可用。
- 不支持的平台和纯 CLI 构建：显示能力不可用，不引入原生依赖。

虚拟屏仍共享登录会话、剪贴板、鼠标、键盘和焦点；本功能不证明发送可靠性或输入隔离。
拔掉实体显示器、锁屏、睡眠、强制结束进程后的精确窗口恢复不在首版支持范围。

## 窗口为什么能显示在虚拟屏

微信按原来的方式渲染窗口。系统将虚拟显示器作为扩展桌面的一部分，aicat 通过辅助功能把窗口
移到该屏幕的坐标范围，由 WindowServer 合成对应屏幕的内容。微信无需修改，也无需增加视频输出接口。

## 来源

原生显示创建与拓扑恢复复用 `internal/workscreen/` 中的 yomado 代码及 MIT 许可证，
来源固定为 `a09cc7e3c749a077c7b9eb1e94959dd05a8d26c4`。原来的
[原型验证](native-display.md) 继续保留；正式管理器和原型共用同一份原生实现。

## 使用

先打开企业微信或 PlayCover 的 iPad 微信，在 aicat 的“设置 → 虚拟工作屏”开启开关。
只搬移允许定位的普通窗口；全屏、最小化和模态窗口不会被自动搬入。若应用随后启动，
可点击“移入微信窗口”再次收集。关闭开关或通过 aicat 正常退出时，先恢复原位置和尺寸。
如果其他应用的窗口被手动放入工作屏，先将它们搬出，才能关闭屏幕。

缺少辅助功能权限时，页面会报告原因；需要用户在 macOS 系统设置中授权当前 aicat 应用。
不会自动重置权限、变更主屏、关闭实体屏、解锁电脑或修改系统睡眠设置。

## 可重复的进程 E2E

### 退出恢复调查（2026-11-03）

真实企业微信出现恢复检查失败。修复前需要区分：AX 拒绝写入、目标屏幕限制尺寸、
位置被系统约束、AX 与 WindowServer 未收敛、原窗口失效。重点最小复现是实体屏上的最大化普通窗口，
它的尺寸可能超过虚拟屏可用区域；不能用小窗口通过的结果推断它也能恢复。
验收必须比较原始位置和尺寸，并保留失败时的 AX/WindowServer 观测；不能放宽精度或跳过恢复确认。

最小复现确认旧实现将原高度 1073 的窗口恢复成 1040：在虚拟屏上先增大尺寸，AppKit 将高度
限制在较小屏幕的可用区域内；之后搬回实体屏没有重新恢复大小。修复顺序为先缩小、定位到目标屏、
恢复目标大小、重新定位。AppKit 的所属屏幕还可能在 AX 调用返回后才更新，因此在既有四秒
收敛预算内读取实测矩形、重新校正尚未恢复的窗口，同时让两端主循环运行；最后仍要求 AX 与
WindowServer 精确匹配原矩形。它只重复可幂等的窗口定位，不重试消息发送。

另一个退出阻塞来自只跨过屏幕边缘 37 像素的实体屏窗口。未登记窗口保护现在比较它在各个活动屏幕上的
重叠面积：主要属于其他屏幕的窗口不会阻止关闭，管理器不主动搬移它们；移除屏幕时，WindowServer 可能
收拢它们越界的部分。主要属于工作屏或归属相同的窗口继续阻止关闭。

使用 `python3 scripts/work-screen-e2e.py --maximized` 验证铺满实体屏的普通窗口；
`--restore-probe` 只做两步管理动作，用于保存根因最小复现，不替代完整验收。

```sh
NODE_PATH=/path/to/node_modules python3 scripts/work-screen-e2e.py
```

测试使用已有的 Playwright 和本机 Chrome，并需要测试入口已有辅助功能及屏幕录制权限。
构建标记 `workscreencheck` 仅将应用白名单替换为临时测试应用，并开放仅本机构建的观察入口；
UI、HTTP 管理路由、窗口管理和显示拓扑验证均使用正式实现，不操作真实微信。
普通 release 不包含该观察入口或测试应用白名单。

每次运行生成独立的 `build/work-screen-e2e/<时间>/`，包含源码和二进制 hash、构建与运行日志、
页面截图、真实虚拟屏窗口截图、AX/WindowServer 位置、拓扑快照及 `report.json`。
缺少权限时记录 `blocked`，不将其算作原生功能通过。测试 HOME 隔离，系统代理始终关闭，不写真实 Keychain。

### Mini 实机验收（2026-11-04）

使用 Mini 原有的 `aicat Local Code Signing` 证书签署完整 app，在覆盖前确认新旧
designated requirement 完全相同，原位更新 `/Applications/aicat.app`。原有辅助功能授权继续有效，
未创建证书或要求重新授权；生产配置的 SHA-256 在更新和验收后保持一致。

在正式 release 中通过辅助功能点击 aicat 设置开关和“退出”，使用真实企业微信、PlayCover iPad 微信
窗口完成开启、关闭、再次开启后退出，以及重新启动验收。窗口位置由 AX 与 WindowServer 双重观测，
退出约 2 秒完成，无强制结束；原进程、窗口身份和原尺寸保留，显示拓扑恢复。企业微信初始左侧越界
1 像素，移除显示器后由 WindowServer 校正到边缘，验收明确记录该差异。

`~/.aicat/deployments/work-screen-exit-20261104-01/aicat.previous.app`。
